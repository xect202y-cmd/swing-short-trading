# 초단기(단타) 데이트레이딩 카테고리 설계

날짜: 2026-07-03 · 상태: 사용자 승인 후 구현 계획으로 전환
관련 repo: `swing-short-trading`(엔진) + `hermes-dashboard`(UI)

## 0. 목표와 원칙

최종 목표는 "어떤 시장상황에도 하루 10만원을 버는 자동매매 시스템"의 검증 파이프라인 구축.
기존 중·단기 스윙(v1~v4, 시드 500만)과 **별도 카테고리**로 초단기 데이트레이딩 모델 2종을
페이퍼 트레이딩 + 백테스트 리플레이로 검증한다.

합의된 원칙:
- **일봉 OHLC 기반 데이트레이딩**(당일 진입→당일 청산, 오버나잇 없음). 분봉 스캘핑은
  무료 데이터 한계(야후 5분봉 60일)로 검증 불가 → 이번 범위에서 제외.
- **조건부 다종목 회전**: 모델당 하루 최대 5종목, 트리거 충족분 전부 진입. 무조건
  반복매매는 수수료 출혈로 기대값이 음수가 되므로 하지 않는다. 미진입일도 사유 기록.
- **하루 10만원의 도달 경로 = 검증된 일 기대값 × 자본 스케일업**. 300만 계좌로 일
  3.3%는 비현실 — 대시보드에 "현재 페이스로 10만원 달성에 필요한 자본"을 정직하게 표시.
- 사실/판단 레이어 분리: 체결·손익은 실측 OHLC로만, LLM/리서치는 종목 선별에만.

## 1. 알고리즘 2종 (서로 반대 시장상황 커버)

### 단타 v1 — 변동성 돌파 (추세 추종형)
- 진입: 당일 `고가 ≥ 시가 + k×(전일 고가-저가)` 이면 트리거가에 매수 체결로 판정 (k=0.5)
- 청산: 당일 종가 전량. **손절은 시뮬레이션하지 않음**(2026-07-03 실증 정정:
  장중 트리거 진입이라 당일 저가가 진입 '전' 아침 눌림일 수 있어, 저가 기반 손절
  판정은 승자를 손절로 오판 — 500일에서 기대값 -1.2%p 왜곡·승률 17%→44%.
  stop_pct(-2%)는 라이브 대응 가이드로 계획에만 표시)
- 필터: 거래대금 하한(스윙보다 엄격), 전일 레인지 노이즈비율 필터
- 강한 장: 상승 추세·변동성 확장

### 단타 v2 — 갭하락 과매도 반등 (역추세형)
- 진입: 시가가 전일 종가 대비 -2% 이상 갭하락 + 전일 기준 상승배열(20>60일선) 유지
  종목을 시가 매수
- 청산: 당일 종가 전량. 손절 -2.5%(동일 보수 판정)
- 강한 장: 하락 변동·과매도 반등

공통 체결 규칙(look-ahead 방지): 트리거가가 당일 고저 범위 안에 있을 때만 체결 인정.
수수료 1.5bps + 슬리피지 5bps(스윙과 동일). 포지션 사이징: 계좌/5 균등.

## 2. 페이퍼 계좌·실행 구조 (swing repo)

- 신규 모듈 `src/swing_trader/scalp/` — strategy(v1/v2 룰), account(가상계좌),
  planner(전일 계획), briefer(디스코드/MD), backtest(리플레이)
- **모델별 독립 가상계좌 300만원 ×2** → `state/scalp_state.json`
  (모델 키: `scalp_v1`, `scalp_v2` — 스윙 paper_state와 완전 분리)
- 신규 CLI `scalp-run --market kr|us`:
  - KR 09:05 런: ①어제 계획의 체결/손익을 어제 OHLC로 확정·정산 ②볼트 리서치 기반
    오늘 계획 수립·발송
  - US 06:00 런: 방금 마감된 세션 결과 확정 + 다음 세션 계획 (동일 흐름)
- 기존 예약작업 bat + 클라우드 workflow(swing.yml) 마지막에 scalp-run 추가.
  failover 마커 키 `scalp_kr`/`scalp_us` (daily_done.json, 기존 구조 재사용)
- 계획 영속화: `state/scalp_plan.json` = { date, market, scenario, models: { v1:[{ticker,
  name, trigger, stop, qty, why}], v2:[...] } } — 다음 런이 이 파일로 정산

## 3. 전일 리서치 기반 플랜 빌더

- scalp-run 계획 단계에서 VaultReader로 **거시 대시보드 + 주도섹터(분기회고) +
  종목뉴스 티어링 + 지침로그(이브닝)**를 읽어 시나리오 산출(리스크온/오프, 포커스 섹터)
- 시나리오로 후보 종목을 필터/가중 → 그 안에서 v1/v2 트리거 계산
- 디스코드 아침 계획에 시나리오 근거("왜 이 종목") 포함
- **그림자 A/B**: 시나리오 필터 OFF(순수 기계룰) 가상 성과를 같은 파일에 병행 기록 →
  리서치 필터의 부가가치 자체를 검증. 백테스트는 기계룰만(과거 뉴스 재현 불가).

## 3b. 실시간 가격 소스 (단타의 생명선)

볼트 종목노트의 가격 필드는 배치 시점 값이라 **가격 용도로는 절대 사용하지 않는다**
(볼트는 시나리오/종목 선별에만). 가격 소스 위계:

- **계획 단계(장중 시가·현재가)**: 신규 `market/realtime.py` —
  KR = 네이버 실시간 시세 API(stock-alert에서 GitHub Actions 호환 검증된 소스 재사용),
  US = 야후(yfinance). KR 09:05 런 시점엔 이미 개장(09:00) 후라 **당일 시가가 실시간으로
  확보됨** → v1 트리거가 = `당일 실시간 시가 + k×전일레인지`(구체 가격으로 계획 발송),
  v2 갭 판정도 실시간 시가 vs 전일 종가로 즉시 확정.
- **토스 API**: 로컬(거주지 IP) 런에서 가용하면 KR 시세 1순위로 사용(정확도↑),
  클라우드 런은 데이터센터 IP 차단 이력이 있어 네이버/야후로 폴백.
- **정산(다음 런)**: 확정 일봉 OHLC가 정본 — 실시간값과 차이가 나면 확정 일봉 기준으로
  체결/손익을 재계산해 기록(페이퍼 검증의 재현성 유지).
- 실시간 소스 전부 실패 시: 그 시장 계획은 "가격 미확보로 스킵"을 명시 기록+경고
  (조용한 누락 금지).

## 4. 디스코드 알림 (스윙과 시각 분리)

- 기본: 같은 Swing Hook 웹훅, **별도 임베드** — 제목 `⚡ 단타 페이퍼 · KR/US`,
  오렌지(0xE67E22), 푸터 "가상 300만 ×2모델 · 데이트레이딩(당일청산)"
- 내용: ①어제(당일 US) 결과 — 모델별 체결 표(종목/진입/청산/손익), 계좌 잔고,
  일손익 vs 10만원 ②오늘 계획 — 모델별 종목·트리거가·손절가·시나리오 근거
- env `SCALP_DISCORD_WEBHOOK_URL` 있으면 그 웹훅으로 발송(채널 분리 옵션)

## 5. 백테스트 리플레이 → scalp_compare.json

- 신규 `scalp-compare` 로직(run_version_compare와 동형): 전 유니버스 500일 일봉으로
  v1/v2를 리플레이, OOS 분리(oos_fraction 동일), 가상 300만 복리 곡선
- 산출 `state/scalp_compare.json` — version_compare.json과 **동일 스키마**(label/title/
  core_logic/oos/equity) + `seed: 3_000_000`
- 기존 version_compare.json(스윙)은 변경 없음(하위호환 100%)
- 주간(금) brief 흐름에서 자동 갱신(스윙 harness와 같은 자리)

## 6. 대시보드 (hermes-dashboard)

### 6a. 버전 비교 화면 — 카테고리 분리
- `/api/compare`: version_compare.json + scalp_compare.json을 읽어
  `{ ok, categories: [{ key:"swing", label:"중·단기 스윙", seed, oos_*, versions },
  { key:"scalp", label:"초단기 단타", ... }] }` 응답(기존 최상위 필드도 유지=하위호환)
- `CompareView`: 최상단 세그먼트 토글 **[중·단기 스윙 | 초단기 단타]** → 선택
  카테고리의 버전들로 기존 A/B 픽커·겹쳐보기·개별 카드 렌더(시드 라벨 500만/300만
  카테고리별). 스윙 선택 시 현재와 동일.

### 6b. 성과탭 10만원 목표 카드 — 카테고리 분리
- 기존 `DAILY_GOAL=100000` 카드(PerformanceView 최상단)를 2행으로:
  `중·단기 스윙`(현행 소스) / `초단기 단타`(신규 `/api/scalp` — scalp_state 읽기)
- 각 행: 오늘 실현손익 · 최근 20일 일평균 · 10만원 달성률 게이지 ·
  **"이 페이스로 10만원엔 자본 X원 필요"**(일평균수익률 기반, 표본<10일이면 "측정중")
- 신규 `/api/scalp` 라우트: swing repo raw에서 scalp_state.json/scalp_plan.json 읽어
  요약(CDN 캐시 120s, 기존 cdnCached 패턴)

## 7. 검증 계획

1. 단위테스트(pytest): 트리거 체결 판정(레인지 밖 미체결·손절 우선·look-ahead 없음),
   계좌 정산, 플랜 직렬화/정산 왕복, 마커 키
2. `scalp-compare` 실행 → scalp_compare.json 생성, OOS 지표 sanity(거래수>0, MDD<0)
3. `scalp-run --market kr` 수동 1회 → 디스코드 임베드 실물 + scalp_plan/state 확인
4. 대시보드: vitest(카테고리 파싱·목표카드 계산) + tsc + build, prod 배포 후
   비교화면/성과탭 실물 확인

## 8. 범위 밖 (명시)

- 분봉 실시간 스캘핑, 실계좌 주문, 장중 반복 재진입(종목당 1회/일 유지)
- 스윙 로직/버전(v1~v4) 및 기존 version_compare.json 변경 없음
